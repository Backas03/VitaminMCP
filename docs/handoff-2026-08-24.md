## 이 보고서의 정정 (2026-08-24, 재검증)

이 보고서를 독립적으로 재검증하면서 세 가지가 사실과 달랐다. 모두 고쳤다.

- **릴리스 워크플로가 깨져 있었다.** `upload-artifact`는 검색 경로들의 최소 공통 조상을 아티팩트
  루트로 삼는다. 러너와 viewer를 각각 단일 경로의 별도 스텝으로 나누면서 아티팩트가 디렉터리 없이
  파일명만 담게 됐고, `build/dist` 로 flat 하게 내려받은 뒤 릴리스 스텝이 `runners/`·`assets/` 를
  찾다 실패한다. Windows 자산까지 함께 깨진 상태였다. download 경로를 각각
  `build/dist/runners`, `build/dist/assets` 로 지정해 고쳤다.
- **`ManagedServerLiveTest`는 클래스 전체로 돌리면 실패했다** — 새 template 테스트가 아니라 기존
  `downloadsAVersionStartsItAndTheAgentAnswers` 가 teardown에서 죽는다. `@TempDir` 안의 Paper jar가
  서버 종료 뒤에도 Windows에서 잠겨 있어 삭제가 실패한다. 2회 재현했고, 새 테스트를 빼면 통과한다.
  두 테스트 모두 공용 Paper 캐시(`PaperDownloader()`)를 쓰게 해서 고쳤다.
- **macOS SEA는 릴리스 때 실패했을 것이다.** postject 호출에 `--macho-segment-name NODE_SEA` 가
  없었고 주입 전 `codesign --remove-signature` 도 없었다. 둘 다 Node SEA가 macOS에서 요구한다.
  덧붙여 러너 이미지 `macos-13` 은 은퇴했고 `macos-14` 는 deprecated라 `macos-15-intel` /
  `macos-15` 로 바꿨다.

작은 것들: README가 아직 배포된 적 없는 Linux/macOS 네이티브 자산을 "available" 로 표기하고 있었고,
`BotRunner.parseInspect` 가 새 필드 두 개를 무방비로 읽어 구버전 러너에서 AIOOBE를 냈으며,
`clientview.mjs` 의 스트림 맵이 despawn 때 정리되지 않았다.

커밋 `166746b`, `8bfdc9f` 의 메시지 본문에는 줄바꿈 대신 literal `\n` 이 들어가 있다. 고치려면
history rewrite가 필요해 손대지 않았다.

## 아직 남은 작업

`docs/next.md` 기준 실제 미완료는 원격 두 번째 머신 검증 하나다. 이전 요청에서 이 항목은
명시적으로 skip했다.

- 실제 TLS keystore를 사용하는 원격 agent
- `session_start`에 `tls: true`
- self-signed certificate fingerprint pinning
- 원격 Paper/Purpur 서버에서 bot 접속까지 확인

이 작업에는 원격 SSH 계정/터널과 TLS fingerprint가 필요하다. 이전 SSH tunnel 실험에서는
agent/server 조회는 성공했지만 bot spawn은 원격 Bungee forwarding 설정 때문에 다음 오류로
실패했다: `If you wish to use IP forwarding, please enable it in your BungeeCord config as well!`
TLS 연결과 fingerprint pinning 자체는 아직 검증하지 않았다.

1.21.11보다 높은 버전 추가는 현재 `docs/next.md`의 완료 항목 밖의 후속 작업이다. 추가할 때는
공식 Paper build 확인 후 반드시 live compatibility gate와 runner bundle coverage를 함께 확인한다.

## 작업 시 주의사항

- 이 머신의 기본 `JAVA_HOME`은 잘못되어 있으므로 모든 Gradle 명령에서 Java 21을 지정한다.
- PowerShell에서는 모든 `-D...` 인자를 따옴표로 감싼다.
- live test property가 해당 module의 `build.gradle.kts`에서 forwarding되는지 확인한다.
- Paper live server의 생존 여부는 `Done (` 문자열만 보지 말고 `latest.log` 첫 줄 timestamp가
  새 부팅 시각인지 먼저 확인한다.
- runner-to-Java protocol의 `RECORD_SEPARATOR`와 `UNIT_SEPARATOR`는 0x1E/0x1F라 diff에서
  보이지 않는다.
- Conventional Commit을 사용하고 `Co-Authored-By` trailer나 AI attribution을 넣지 않는다.
- push/tag/release는 하지 않았다. 배포는 사람이 결정한다.
